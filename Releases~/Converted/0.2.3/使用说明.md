# 0.2.3：DeepZoom ASE 可编辑图

先在 Unity Package Manager 选择 Add package from tarball，安装 `Releases~/com.aseshader.handwritten-converter-0.2.3.tgz`。项目需要已安装 ASE 1.9.9.13。UI 图使用新版插件自带的模板，请先更新插件，再导入本目录的 Shader。

把需要的 `.shader` 拖入项目 `Assets` 新位置，再通过 ASE 打开：

| 文件 | Shader 名称 | 图内容 |
| --- | --- | --- |
| DeepZoomPageTable360_ASE_Organized.shader | DeepZoom/DeepZoomPageTable360_ASE_Organized | 79 个计算原生节点、9 个 Register、11 个 Get、13 个中文 Comment |
| DeepZoomPageTableUI_ASE.shader | DeepZoom/DeepZoomPageTableUI_ASE | 96 个计算原生节点、12 个 Register、16 个 Get、15 个中文 Comment |

两图均无 Custom Expression，由 ASE 实际保存、重载并通过 Unity 编译；交付文件与已验证输出字节一致。节点依据连线从左到右排列，Comment 解释每个计算步骤，长数值线通过命名的 Register/Get 引用。纹理对象靠近采样器摆放。

重新生成时，打开 `Tools → ASE Shader Converter → 打开转换器`，选择原手写 Shader，点击“分析”，通过后点击“生成并验证”。“高级：节点排列与功能说明”中的排列、中文 Comment 和长线 Register/Get 默认开启，可以分别关闭，也可以调整长线距离。这些选项用于生成新图；已有 ASE 图输入仍走迁移流程。

360 整理版使用独立的 `_Organized` Shader 名称，可与旧版转换结果同时存在。测试材质需要选择相应的新 Shader，再检查纹理和属性绑定；运行时代码如使用 `Shader.Find`，也需要使用新名称。UI 图保留 16 个原属性，以及 Stencil、ColorMask、GUI 深度测试、顶点色乘 Tint、直通 Alpha 混合、硬裁剪和两个全局 UI 关键词。UI 适配器仅支持已审核的源码版本，行为改变后需重新适配。

验证环境为 Unity 2022.3.10f1 / ASE 1.9.9.13 / Built-in / Windows D3D11。360 的六组和 UI 的 21 组固定状态画面对比均为 RGBA 最大误差 0。尚未比较用户实际球体、Canvas、Mask 或 RectMask2D 场景，报告中的 `visualComparisonPassed` 因此保持 false。请在原场景测试材质后再替换正式材质。

ASE 将空 2DArray 默认标记写成 `white`，不会自动提供实际纹理数组；请检查 `_TileArray` 的运行时绑定。本目录不携带原材质、运行时纹理、场景、用户原始 Shader 或 ASE 源码。

`*-generation-response.json` 是隔离项目的原始生成响应，路径指向当时的生成位置。`360-submitted-plan.json` 是测试入口提交的中间节点计划，`ui-plan.json` 是 UI 生成响应中的计划；Register/Get 和 Comment 由 Editor 建图阶段加入。`verification.json` 记录输入与输出 SHA-256 和验证范围。
