# ASE 着色器库（0.3.5）

入口为 **Tools → ASE Shader Converter → ASE 着色器库**，主转换窗口也有入口。支持材质分类、Built-in / URP / HDRP、Mobile / Pad / PC、低/中/高复杂度与组合关键词检索；可按材质、复杂度、设备分组，一键安装筛选结果的 Shader 并创建 `.mat`。完整操作与分级依据见 [设备与批量生成](LibraryTargets.md)，全部方案见 [库索引](ShaderLibraryIndex.md)。

人物材质的输入、语义、宿主、成本与验证要求已合并到对应分类的“材质说明与适配要求”，保留环境 probe/模板 describe。分类下拉显示当前目标管线的实际图数，“分类收录总览”显示全部管线及缺口。没有匹配项时说明缺版本或筛选限制，并提供查看其他版本/重置入口。研究来源使用独立分类与计数，不进入可安装清单。

0.3.3 新增自然暗角、模拟信号故障、数字故障与历史帧混合、镜像与万花筒。可以搜索 `Kino`、`滤镜`、`万花筒`、`DigitalGlitch` 并结合设备/管线筛选。这四个同源方案的 12 个 ASE 版本是显式输入纹理滤镜：生成材质后需绑定输入并由宿主全屏绘制；不会自动注入相机。数字故障需外部噪声及历史帧，模拟故障需外部更新动画参数；这些原 C# 宿主没有移植。原 Shader 的 RGBA、深度/混合和万花筒全局关键词在限定输入输出范围内映射，详情见 [本轮证据](Evidence/PublicLibrary033/README.md) 与 [MIT 声明](ThirdPartyNotices.md)。

本轮下载 41 份源码并完成 123 次三目标核心分析；37 个新研究身份进入“来源研究与待适配”，其 Surface 光照模型和编译语义仍需适配。四份 Kino 是原研究身份的显式计划适配，主转换器自动规划仍不能直接转换这 41 份输入。研究总数为 1,079，与可生成图分别计数。

同一卡片显示 Built-in/URP/HDRP 对应版本、同源身份、共同功能、各目标的具体缺口与宿主条件。20 个 HDRP 原图适配仍缺 40 份目标版本；原图缺失的 SSS、Hair、Fabric、SSR、Decals 和深度 Pass 有明确原因，不以普通 Lit 或近似水冒充已完成对应。原有 14 个基础与 70 个效果扩展仍保留，扩展含实际原生计算，不能将 210 份文件说成 210 种独立算法或网上源码转换。

性能档位为静态复杂度，设备是候选目标，全部标记未实机测速。每项显示采样位置、节点、透明/顶点/模型成本、Shader Model 要求与验证 API。HDRP 只归 PC；例如 URP Lit 默认 target 4.5 的图需要手机/Pad 满足相应功能级别。不能将 D3D11 编译通过扩大为 Android/iOS/Metal/Vulkan/GLES 已验证。

14 个基础分类为皮肤、毛发、眼球、衣服布料、丝袜与薄织物、水、金属、石头、玉石、UI、UI 动效、特效、UV 动画、顶点动画。原图中未能确认具体材质类型的通用表面/工具图放在 General，避免把所有 Lit 图都称为金属。

所有可导入条目都由实际 ASE API 生成，经过保存重载、Unity Shader 编译、节点位置及 Comment 成员检查；均使用原生节点，Custom Expression 为 0。验证环境是 **Unity 2022.3.10f1、ASE 1.9.9.13、URP/HDRP 14.0.8、D3D11**。这些结果不代表其他 Unity/ASE 版本和图形 API 已验证。

新增库完成了当前生成配置的编译及导入后 Pass 检查，没有穷举每张图的全部材质关键词组合和所有辅助 Pass。DeepWater 的历史 22 组开关测试单独记录，不能扩大为其余条目的变体验证。

原创基础图是供编辑和扩展的起点。HDRP 皮肤/玉石基础使用 Lit 的 SSS/Transmission 及可绑定的 Diffusion Profile；毛发基础使用实际 Hair 模板；织物基础使用 Fabric 模板。Built-in/URP 对应条目保留各自能力范围，不能视为同一 BSDF 的等价移植。基础水面只提供流动坐标与水色；完整深度水单独列出。丝袜示例为独立外层网格上的覆盖/织纹近似，未验证皮肤叠层、拉伸、透明排序及远距摩尔纹。

## 原图适配和剩余阻塞

20 张本地图覆盖三版 `Girl_Hair`、三版 `Eye`、`Fabric_Trans`、`Fabric`、demoteam Hair 参考，以及部分 SF_Base、玻璃/遮罩/顶点色表面、管道、Unlit、RGB 与 Golem 图。名称相同而 SHA-256 不同的版本分别记录。

这些是**需要绑定原材质资源的适配图**。保留属性引用名并记录默认纹理 GUID；没有携带原项目纹理、材质、角色、扩散资产、仿真及帧设置。原图已禁用的部分输出计算保留为断开分支，清单中的 `inactiveOutputs` 解释原因。运行 `Tools~/Plan-LocalShaderGraphs.py` 可在本地只读缓存存在时重新创建显式节点计划，再通过实际 ASE API 生成。

本地 Eye 源图实际使用 HDRP Lit/SSS 与虹膜运算，因此按其真实源模型适配。它不是专用 Eye BSDF 的证明，也没有把专用 Eye 模型替换成普通 Lit。当前 ASE 安装没有独立 Eye 或 StackLit 模板；源 StackLit 仍保持阻塞。

100 张唯一 Shader Graph 中，本版适配并生成 20 张，另外 80 张保留具体阻塞。主要包括旧格式迁移、StackLit/FogVolume/Decal 等材质模型、关键词、顶点阶段、渲染状态/运动矢量、外部子图/函数及尚未映射的原生节点。52 个子图均已解析和记录依赖，不能当成独立可渲染材质。57 个本地 `.shader` 中另有两份旧 ASE 图；一份依赖旧模板，另一份还含函数 GUID 和 Custom Expression，未作为完整可用库条目打包。详细数据见 [本地证据](Evidence/LocalLibrary030/README.md)。

[原图剖析索引](LocalGraphAnalysis.md) 列出全部 100 张图的活动模型、节点/属性数量和当前阻塞，并逐一说明 20 张适配图的输出、模板状态、功能阶段与资源 GUID。

**尚未进行原角色、原场景的画面等价比较，也没有 3A 画质或 GPU 性能认证。** 用户需要先绑定资源，再在实际模型、灯光、曝光、相机和目标平台下比较效果。

## 导入与使用

1. 在项目安装 ASE 及对应管线模板，再安装本插件。打开分类库，选择与当前项目一致的管线。
2. 选择分类、设备、复杂度，搜索可用空格组合，例如 `金属 氧化 URP`。展开卡片点击“安装此项 Shader + 材质”，或点击“一键安装筛选结果”。插件核对 SHA-256、验证标记和当前管线，在 `Assets/ASEShaderLibrary/<分类>/<管线>/` 创建图及 `.mat`；相同 Shader 和已有匹配材质复用，用户修改保留，冲突文件避让。其他管线不会一起导入。
3. 用 ASE 打开导入的 Shader。图按依赖从左到右排列，复杂功能组按阶段拆分；中文 Comment 解释用途，远距离数值采用 Register/Get。
4. 原创材质会配置配色及适用属性的小型程序示例纹理，放在 `Assets/ASEShaderLibrary/Shared/OriginalExamples`，并通过公开 ShaderGUI 初始化混合、关键词和 Pass；原创发卡开启裁剪。可以换为实际贴图。HDRP SSS 仍需创建和登记 Diffusion Profile 并绑定；毛发需正确的切线/根梢/覆盖数据，织物需正确的织纹尺度与方向。
   原图适配还需要恢复源材质的开关和数值。特别是模板使用 `Alpha Clipping=Material Toggle` 时，要按源材质启用 Alpha Clipping / Shadow Threshold；源图计划端口存在不表示新建材质的所有关键词已开启。默认纹理的白/黑/法线类型与 NoScaleOffset 属性已按源声明保留。
5. 对照条目的限制及原材质，检查正反面、Alpha/阴影、曝光、近远距离与动画。编译通过本身不证明行为相同。

库文件保存在 `Samples~/ShaderLibrary`，Unity 不会自动导入全部三管线图。可导入清单与研究记录保存在 `Editor/Resources/ASEShaderLibraryCatalog.json`。JSON API 请求 `{"schemaVersion":1,"operation":"library"}` 返回同一份清单；研究结果也保留在 `rules`/`analyze` 与人物材质窗口。

## 完整 DeepWater

DeepWater 现在有 Built-in、URP、HDRP 三个 ASE 版本，共用同一组计算、参数、八组本地关键词与中文功能区。批量生成会创建线性波纹/焦散示例纹理，并同步每个新材质的八组 Float 与关键词；旧材质保留用户修改，不强制重置。完整工具/预制体按钮仍只适用于 Built-in，避免将 Built-in 相机组件导入 SRP。

URP 需启用 **Opaque Texture、Depth Texture**，并将 Universal Renderer 的 **Copy Depth 设为 After Opaques 或 Force Prepass**；若在透明之后才复制，水面渲染时读不到当前水底深度，可能没有吸收与深浅变化。HDRP 需 **Color Pyramid、深度缓冲、默认透明阶段与 Reflection Probe**。水底必须是不透明且写深度的几何体，水面需有足够网格细分。SRP 的背景采样不包含后续透明物体。HDRP 采样去预曝光后进入 Emission，独立高光/环境反射开关仍列为缺口。模板灯光、雾和拷贝宿主不同，尚未证明三管线像素等价。

Built-in 需要完整水面时，点击条目的“安装完整 DeepWater 配套工具”，安装 `Assets/Shaders/DeepWater_ASE.shader` 和原创深度组件。等待脚本编译完成后，执行 **Tools → ASE Shader Converter → Water → Create supporting assets**。工具创建原创斜率/焦散纹理、细分网格、材质预设和预制体，不需要复制其他工程的资源 GUID。

将生成的 `Assets/Shaders/DeepWater/DeepWater.prefab` 放入有不透明水底的场景。单独给 Plane 赋材质时，仍需 `DepthWaterSurface` 请求相机深度，且应有足够网格细分。浅/深水颜色的 A 不控制透明度；水深、吸收 RGB、Density 与 DeepDistance 控制透射和深浅着色。已有同路径文件会阻止重复安装，保留用户内容。详细参数与历史 22 组开关渲染证据见 [水面说明](../Samples~/Water/README.md)。

## 来源记录

研究页共 1,079 条来源身份记录：固定公开清单 760 条、后续新增的已安装 HDRP 版本参考 16 条、此前用户 Shader 参考 11 条、本地按内容去重的 255 条，以及 0.3.3 新增的 37 条。人物研究的另 19 条公开来源已在固定清单内；四份 Kino 也是旧来源身份，因此不再次增加。同一固定提交/路径的 LF 与 CRLF 仅是字节格式差异，在证据中记录别名并保留历史 SHA-256。来源身份不等于全局唯一算法数。

此前已实际验证的输入按 SHA-256 关联 FullValidation028 的三管线结果，研究页显示历史生成/图迁移、编译和固定 fixture 比较状态。历史已验证、当前可自动规划、当前可导入的库图分别保留原含义。

本地 21 个压缩包均按数据读取；`Alien.zip` 是播放器构建，未找到选定的 Shader 源码，不能计为已解析一套源码工程。另记录 2,822 条材质关联及 62 条工程版本/管线清单元数据，含解压/压缩包重复来源。没有找到名字明确为丝袜的本地材质，因此本版不宣称已经复刻该项目的丝袜效果。

原始参考 Shader、Shader Graph、纹理和 ASE 软件源码不随包分发。本地图适配供本次用户工作区使用，原素材条款继续适用；不据此主张公开再分发权利。网上素材保留来源、许可、哈希和阻塞，未把“已研究”标成“已生成”。
