# 0.3.4 统一着色器库与分类审计

本轮针对重复人物窗口、实际图与研究资料混合、默认严格映射筛选导致人物分类空白进行重构。没有新增 ASE Shader，没有重新执行节点生成或像素测试，没有解决现存专用模型和跨管线适配阻塞。

入口为 **Tools → ASE Shader Converter → ASE 着色器库**。实际图和来源研究共用同一个窗口，分别筛选与计数。皮肤、毛发、眼球、布料的输入资源、颜色空间、宿主依赖、管线要求、验证要求和参考模板检查嵌入对应分类；独立人物菜单移除，旧代码入口跳转到统一库。

默认范围是当前工程管线的全部已 ASE 保存重载并经 Unity 编译的图。三目标功能映射仍可主动筛选，不再默认隐藏人物基础图。卡片继续显示三目标状态、同源身份、功能缺口及宿主要求。分类下拉只依据实际已验证图建立，并显示所选管线的图数。研究页只列有来源的类别，研究数不计为可安装图。

分类收录总览与空结果提示区分三种情况：已有图被搜索/设备/复杂度/功能筛选排除；当前管线确实缺少版本；只有研究记录、尚无实际图。提供重置筛选、查看该分类其他管线版本及研究/实际图互相跳转。历史两条 UIAnimation 研究记录在查询层归并 UIEffects，避免出现独立的空分类；原来源身份与目录数据保留。

本轮验证：

- `dotnet run --project Tests/CoreChecks.csproj --no-restore`：540 项通过，新增覆盖真实图/研究隔离、分类计数、默认人物可见、严格映射筛选、空组合和旧 UI 类别归并。
- `dotnet build Tests/EditorCompile.csproj --no-restore`：0 警告、0 错误。
- `Tests/UnityLibraryBrowserSmoke.cs` 在 Unity 2022.3.10f1 / ASE 1.9.9.13 / D3D11 三个隔离工程实际执行 probe、library API、窗口导航、旧入口跳转、重置、IMGUI 事件、分类逐项安装和图校验。Built-in 70 项、URP 70 项、HDRP 72 项通过；实际各安装一个图和材质覆盖 14 / 14 / 15 个有内容分类。GUI 检查为程序化事件与状态检查，未做人工交互或截图视觉验收。
- `Tools~/Verify-LibraryBrowser.py`：对照固定 SHA-256 的 0.3.3 发布包，确认 entries、research、familyContracts、scope 完全未改；重新核对全部 287 个图的 SHA-256。三环境新结果时间均晚于各自启动时间；独立计算分类数量并与 C# 结果逐类核对。见 [verification.json](verification.json) 和 [coverage.json](coverage.json)。

复现：先完成共享 C# 修改，再运行 `Tools~/Run-LibraryBrowser.ps1`。不得在隔离 batch 活跃期间继续修改共享 C#。脚本移走旧结果并保留每次启动记录；本轮早期 UIAnimation 分类审计失败和 Unity 许可握手失败保留在 `.build~/LibraryUI034/Attempts`，不当作成功结果。成功三目标摘要复制为 `Browser-BuiltIn.json`、`Browser-URP.json`、`Browser-HDRP.json`。脚本只有在全部新结果通过时生成 verification。

本轮不重复既有图生成或渲染，Shader 实际生成/重载和渲染证据仍来自 [PublicLibrary033](../PublicLibrary033/README.md)、[CrossPipeline032](../CrossPipeline032/README.md) 及其引用的历史批次。仍为 89 个三份图齐备方案、64 个三目标限定功能映射方案，通用跨管线视觉等价确认数为 0。
