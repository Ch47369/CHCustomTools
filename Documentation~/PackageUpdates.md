# 插件检查与更新（0.4.5）

Shader转换器使用私有 Git 仓库安装。0.4.1 增加 Unity Package Manager 公开扩展区域：选中本包后，详情下方显示“Shader转换器 · 插件更新”。**只有发现比当前安装版本更高的正式标签，才显示“更新到 X.Y.Z”按钮**；未检查、检查失败、版本相同或仓库版本更旧时均隐藏。通过顶部 `Tools/Shader` 打开转换器，主窗口直接显示当前版本、检查更新、状态与更新按钮。检查、升级和错误提示均在当前窗口完成，不另开更新窗口；旧版公开更新入口也跳转到同一个转换器主窗口。

Unity 注册表包通过注册表查询版本，因而具有原生工具栏更新按钮和左侧“更新”列表。Git 包没有这套版本发现机制。本插件使用公开 `IPackageManagerExtension` 添加详情区域，不修改 Unity 内部 UI，也不会把 Git 包加入注册表的“更新”列表。

## 第一次安装带更新入口的版本

0.4.0 及更早版本还没有更新器，需在 Package Manager 中用 **Add package from git URL** 安装一次：

```text
https://github.com/Ch47369/ShaderConverter.git#v0.4.5
```

已配置 SSH 的电脑也可以使用：

```text
ssh://git@github.com/Ch47369/ShaderConverter.git#v0.4.5
```

仓库仍为私有。本机必须安装 Git，并已通过 Git 凭据管理器或 SSH 认证有访问权限的账号。更新器不读取、保存或展示访问令牌；安装 URL 中也不应嵌入令牌。网页能打开仓库并不等于本机 Git 已认证。

## 日常更新

1. 打开项目后，更新器在编辑器空闲时自动检查；选中 Package Manager 中的 Shader转换器或打开转换器主窗口也会触发检查。可用“检查更新”立即刷新。
2. 更新器通过当前安装使用的 HTTPS 或 SSH 地址查询 `vX.Y.Z` 正式标签，按数字版本比较。预览标签、分支和低版本不会作为升级目标。
3. 有新版本时，点击“更新到 X.Y.Z”。Unity Package Manager 解析并安装 `#vX.Y.Z`，完成脚本重载后显示确认信息。安装锁定在该标签，不自动跟随 main 分支。

后台每小时检查一次；成功结果在当前编辑器会话内缓存，脚本重载不会重复查询。失败后的后台重试间隔为五分钟，手动检查可立即重试。检查和版本发现会自动执行，安装升级需要点击按钮。Git 检查最长等待 30 秒；检查期间不弹出认证窗口。首次认证应在系统 Git 工具中完成。安装错误由 Package Manager 提供详细信息；解析过程中不要并行修改项目包依赖。批处理模式不定时联网，但显式打开本包详情/转换器主窗口仍可执行检查。

## 本地安装与其他来源

从目录或 Tarball 安装时，有新版本同样显示“更新到 X.Y.Z”，更新后使用官方私有 Git 标签；本地源码目录、Tarball 文件会保留。仓库版本与本地版本相同时，“更新”按钮隐藏，单独提供“改用 Git 安装当前版本”操作。低版本不允许更新或切换。若要保留当前项目正在使用的本地开发包，继续使用本地引用即可。

嵌入项目 `Packages` 的源码包需要先备份并移出该目录，再通过 Git URL 安装。来自其他 Git 仓库或 fork 的包应在其来源仓库管理版本，更新器不会改写其来源地址。其他注册表来源也不由此更新器接管。

版本检查与 UPM 扩展的验证独立于 Shader 转换后端的支持范围。Unity 6 上的更新器检查通过不表示 Shader Graph 17 的建图后端已经适配；转换支持仍按 [图格式路线与限制](ShaderConversionRoadmap.md) 执行。
